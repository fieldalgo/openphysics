# 변경 기록

[English](../../../../CHANGELOG.md) | **한국어**

OpenPhysics 배포판 여덟 개(`galerkin`, `galerkin-refsol`, `meshine`, `gmshio`,
`physmat`, `simcase`, `sipi`, 그리고 `openphysics` 메타 배포판)는 하나의 버전 번호로 함께
릴리스됩니다. 이 문서는 릴리스마다 바뀐 점을 기록합니다. 형식은
[Keep a Changelog](https://keepachangelog.com/ko/1.1.0/)를 따릅니다. 기준 문서는 영어판
`CHANGELOG.md`입니다.

## 0.x의 안정성

0.x 릴리스는 알파입니다.

- 모든 패키지의 Python API는 마이너 릴리스(0.1에서 0.2)마다 바뀔 수 있습니다. 패치
  릴리스(0.1.x)는 버그를 고치며 API를 바꾸려는 것이 아닙니다.
- 0.x 동안 바뀌지 않는 것은 Python API가 단위와 이름을 나타내는 방식입니다. physmat,
  galerkin, refsol의 공개 함수·클래스·결과는 physmat 레지스트리 이름(`physmat.units`)으로 SI
  값을 받고 돌려줍니다. 물리량은 차원 있는 기본값이 없는 키워드 인수이고, 숫자 대신 텍스트를
  넘기면 `TypeError`가 납니다. 복소수 값은 exp(-i omega t)를 따릅니다. 수동 손실의 허수부는 음수가
  아닙니다. `galerkin.kernels`, `physmat.kernels`와 밑줄로 시작하는 모든 모듈·이름은
  내부용입니다. 자기 단위를 따로 쓰고 simcase와 sipi가 부를 수 있지만, 아무것도 약속하지 않으며
  어떤 릴리스에서든 바뀔 수 있습니다. 단위·이름 배치가 없앤 이름에는 별칭이 없습니다. 그 이름을
  담은 릴리스가 없었기 때문입니다.
- JSON 모델 문서 형식 `"openphysics": "0.3"`은 계약입니다. 이 형식으로 유효한 문서는 계속
  유효하고 뜻도 그대로입니다. 이를 깨는 변경에는 새 형식 버전을 붙입니다. 형식 0.2 문서는 읽지
  않습니다. 모든 읽기가 무엇을 대신 써야 하는지와 함께 이름을 밝혀 거부합니다(`openphysics`에서
  `E-FORMAT`).
- 저장 결과의 형식·필드 layout 식별자(예: `thermal.steady2d-result-v3`,
  `cavity3d-edge-v2`)는 계약입니다. 어떤 식별자가 붙은 파일은 그 layout을 유지합니다.
  layout이 바뀌면 새 식별자를 붙입니다.
- 단위·이름 배치 이전에 결과, Studio 페이로드, 어댑터가 달던 식별자는 모두 은퇴했습니다. 은퇴한
  식별자는 다른 layout에 다시 쓰지 않으며, `simcase.export`는 은퇴한 필드 layout을 단 파일을 이름을
  밝혀 거부합니다(`simcase.export.RETIRED_LAYOUTS`가 각각을 대신한 layout을 적습니다).
  - 결과 형식: `thermal.steady2d-result-v1`, `thermal.steady2d-result-v2`,
    `thermal.transient2d-result-v1`, `thermal.transient2d-result-v2`,

    `thermal.axisymmetric-regions-result-v1`,

    `mechanics.elasticity2d-result-v1`, `mechanics.thermoelastic2d-result-v1`,
    `mechanics.elasticity2d-regions-result-v1`, `mechanics.thermoelastic2d-regions-result-v1`
  - 필드 layout: `thermal2d-p1-node-cell-v1`, `thermal2d-p1-node-cell-boundary-v2`,
    `thermal2d-transient-p1-node-cell-v1`, `thermal2d-transient-p1-node-cell-boundary-v1`,

- `simcase.providers`의 물리 공급자 프로토콜(프로토콜 버전 1, entry point 그룹
  `openphysics.providers`)은 0.x 동안 불안정합니다. 공급자 속성, manifest 구성, 공급자 목록은
  마이너 릴리스마다 바뀔 수 있습니다. 공급자는 자신이 구현한 프로토콜 버전을 밝히며, simcase는
  다른 버전의 공급자를 이름을 밝혀 쓸 수 없음으로 표시합니다.

각 패키지가 구현하는 범위와 한계는 [개요](overview.md)에 있습니다.

## [Unreleased]

- `simcase`: Studio 작업대에 Joule 가열 애플리케이션과 Installed physics를 배치했습니다. **Run Joule heating study**는 리본 Compute 묶음에 있고, 리본의 **Physics → Installed**가 **Installed physics**를 엽니다. 이 패널은 이제 Workspace tools 옆 상태줄 패널입니다(한 번에 하나만, 모든 페이지에서). Joule 실행 뒤 하단 해석 영역의 **Solver log**가 Picard 반복 횟수, 마지막 |ΔT|와 Δσ/σ, 세 전력 수지를 보여 주고 반복마다 나열하며, Settings에는 수지가 남습니다. Connections는 Joule의 두 인터페이스를 노드로 그리고 Joule heat 선과, σ(T) 재료가 있으면 온도 → 전도율 선을 더합니다(설정 전용 배지와 인터페이스 체크 상자 없음). 영역 그림은 밝은 색을 씁니다. 광학 단면은 선택한 형상과 경계를 다시 주황색으로 표시합니다(밝은 색 체계에서 파랑 위 파랑이 되었음). 1000 px보다 좁으면 Run이 보이도록 리본에서 Physics를 빼며, Escape로 두 상태줄 패널 중 열린 것을 닫습니다. 파일 의미, 단위, route, Joule·공급자 계약은 바뀌지 않습니다.

- Studio 결과: 광학 그래프 높이를 데스크톱 작업 영역에 맞추고 완료 후 비활성 작업 버튼을 숨깁니다.

- Studio: 명령 리본, 인접한 모델/설정 패널, Graphics, 스터디/메시지 영역, 두 열 치수 입력과 키보드 패널 크기 조절을 갖춘 밝은 CAE 작업대로 재설계했습니다. 기존 솔버·파일·연결 동작은 유지합니다.

- Studio 연결 보기: 색상 포트와 곡선 연결선이 있는 공간적 노드, 읽기 쉬운 포트 문구, 패널 크기를 따라가는 연결선, 그래프 아래 스터디·검사 패널.

- `galerkin`: **형상 motion은 실수 float64 스칼라가 아닌 `t`를 이름을 밝혀 거부합니다**(dtype을 밝힌 `TypeError`). `motion=`을 받는 모든 풀이기(정상 열, 정상 전기 전도, 탄성, 열탄성 두 경로, 과도 열, 도파관 모드의 `solve_waveguide_modes`와 커널)가 그렇습니다. 전에는 복소 JAX·PyTorch `t`의 허수부가 말없이 버려졌고(0.5+0.25j를 0.5에서 풀었음), PyTorch float32·float16·bfloat16 `t`(또는 `jax_enable_x64`를 켠 JAX의 float32)는 float64로 승격되었습니다. `jax_enable_x64`가 꺼진 JAX는 원래의 거부와 메시지를 그대로 받습니다. float64 `t`의 결과와 미분은 전과 같습니다. [형상 미분](packages/galerkin/shape_derivative.md#거부).
- `simcase`: **`joule.temperature2d` 문서가 Newton 방법을 고릅니다.** 선택 키 `iteration.method`(`"picard"` 또는 `"newton"`)이며 직사각형과 이름 붙은 재료 영역 모두에서 씁니다. 없으면 전처럼 `"picard"`입니다. slot 표 기본값이 없으므로 이 키가 없는 문서는 전과 바이트 단위로 같게 검증·실행·저장됩니다(`defaults_applied`도 그대로). `"newton"`은 galerkin `solve_temperature_joule_heat`를 `method="newton"`과 같은 수렴 검사로 부릅니다. `"newton"` 옆에 쓴 `relaxation_factor`는 이름을 밝혀 거부하고(`E-CONTRACT`; Newton은 완화를 쓰지 않음), `method`의 다른 값은 `E-VALUE-FORM`입니다. Newton 요약은 `iterations` 앞에 `iteration_method: "newton"`을 더하고, Picard 요약에는 이 키가 없습니다. Studio의 Joule route는 Newton 문서를 이름을 밝혀 거부합니다(`unsupported_iteration_method`). 반복 상한이 Picard 걸음을 세기 때문입니다. 검사 N1–N8(`tests/simcase/test_joule_temperature_newton.py`): 출하 예제에서 Newton은 Picard의 26번 대신 3번 반복하고 9.0e-12 K 안에서 같습니다. 기본 Picard가 100번에서 멈추는 galerkin 서미스터(7 1/K)에서 Newton은 4번에 수렴하고, 두 재료 띠는 닫힌 해 차수 2.1을 유지합니다([계약](packages/simcase/electric_joule.md#문서에서의-newton-반복)).
- 문서: validation3d.md(3D 메셔 계획)가 C9를 정의합니다. 상자 공진기 [0,1]³ 바닥에 선 유전체 블록 [0.25, 0.75] × [0.25, 0.75] × [0, 0.5], 영역 2개, 크기는 C2와 같습니다(2026-11-20 수정 기록, 영어·한국어; 기준값 변경 없음). 치수가 없어 C9를 만들 수 없었고, 그래서 V7·V26·V29를 돌릴 수 없었습니다.
- `meshloom`: `meshloom.generate3d(points, facets, segments=None, *, h, domain="regions", region_points=None, facet_tags=None, quality="practical", alpha=ALPHA, max_points=0)`가 공개 메셔입니다. 크기(숫자 하나, 또는 `h={이름: 크기}`로 이름 붙은 영역마다)와 반지름-변 비 한도(`quality="practical"`, `PRACTICAL_RATIO` = 1.4, 또는 `"guaranteed"`, `GUARANTEED_RATIO` = 2)로 제약 Delaunay 세분화를 합니다. 경계 면과 노드는 facet tag로 묶여 `galerkin.from_mesher`가 그대로 읽고, 타입 있는 오류를 내보냅니다. `ALPHA` = 0.9181은 단위 정육면체 h = 0.06에서 변 길이/h의 중앙값이 계획의 기준선과 같도록 보정한 값입니다. 계획 대비 측정: V22(C3 층 전도)는 3e-15까지 정확하고, V23(h = 0.11의 비정형 PEC 공진기)은 통과합니다. V21은 계획의 CI 크기 {0.25, 0.177, 0.125}에서 실패하고(L2 기울기 1.530, H1 0.742) {0.2, 0.1, 0.05}에서 통과합니다(2.293, 1.161). V8은 C2 h = 0.06·0.03에서 통과하고 C2 0.12와 die를 h/2로 한 C3에서 실패합니다. V32의 공진기 세분화 사다리는 성립하지 않습니다(h = 0.25, 0.16, 0.11에서 오차 0.0009, 0.0102, 0.0067).

- `meshloom`: `mesh_plc(..., h=, ratio=, alpha=1.0, max_points=0)`가 메시를 세분화합니다(반올림 전 제약 Delaunay 세분화). 침범된 subsegment·subfacet과, 외접 반지름이 `alpha·h`를 넘거나 반지름-변 비가 `ratio`를 넘는 사면체를 정확한 점에서 나누며, 삽입마다 점에서 보이는 사면체만 지웁니다. 입력 각이 60° 미만인 곳의 규칙(동심 껍질, 그 각으로 만나는 면 사이의 분할 없음, 그 각 때문에 가는 사면체의 비율 분할 없음)이 연쇄를 멈추고, 남긴 사면체와 제약은 `stats`에 셉니다. 점 상한(지정값, 또는 크기 장과 가장 짧은 입력 변에서 유도)에 닿으면 멈추지 않고 새 `RefineError`를 냅니다. C10 입력 14개가 모두 크기의 ¼인 h와 비율 2로 끝까지 세분화되고 V1–V4를 통과합니다. V7(비율 2, 최대 반지름-변 비 ≤ 2(1 + 10⁻⁹))은 C2와 C3의 계획 크기 세 가지에서 통과합니다(최대 1.356, 1.593). C9는 계획에 치수가 없어 돌리지 않습니다. 세분화는 느리고(노드 19,000개에 25초) 아직 단계적 크기 지정과 sliver 제거가 없습니다.

- `simcase`: 새 예제 `joule_temperature_regions`(`examples/simcase/joule_temperature_regions.json`)는 처음으로 제공하는 영역 `joule.temperature2d` 문서입니다. 2 × 1 mm 띠에서 `linear_resistivity` 금속과 상수 500 S/m 저항체가 직렬이고, 300 K와 320 K로 고정한 양 끝 사이에 0.2 V를 걸며, 요소 크기는 0.125 mm입니다. 새 시험이 독립 1D 해(금속에서 삼각함수, 저항체에서 포물선)와 비교합니다: 온도 오차는 상승의 1.9e-3, 단자 전류는 상대 1.3e-6. 지원 문서 표에 올렸습니다. [문서](packages/simcase/electric_joule.md#재료-영역-온도-의존-joule-가열).
