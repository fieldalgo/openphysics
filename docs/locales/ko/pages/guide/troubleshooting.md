# 모델·솔버·결과 오류 진단하기

[English](../../../../guide/troubleshooting.md) | **한국어**

[문서 홈](../index.md)

입력을 바꾸기 전에 어느 단계에서 실패했는지 구분하세요. 원래 모델과 전체 오류 메시지를
보존합니다. 입력 거부, 수치 해석 실패, 뷰어 미지원, UI 결과 만료는 서로 다른 문제입니다.

## 먼저 확인할 사항

| 증상 | 첫 확인 | 적절한 다음 조치 |
|---|---|---|
| Import 실패 또는 필요한 속성 없음 | 활성 Python 환경, 로컬 설치, 작업 위치 | 저장소 루트에서 실행하고 필요한 로컬 패키지를 함께 설치 |
| 알 수 없는 필드·타입·단위·영역 | 정확한 문서 계약, 영역 이름과 재료 이름 | 입력을 validate하고 해당 필드를 수정; 의도한 물리를 조용히 삭제하지 않기 |
| 정상 열의 온도 기준 없음 | 연결 성분마다 Dirichlet 또는 양의 Robin 지지 | 물리적인 온도 기준 지정; 정상 해석의 단열만으로는 기준이 생기지 않음 |
| 기계 강체모드·구속 오류 | 물리 지지와 독립적인 구속 모드 | 실제 지지를 수정; 오류 제거만을 위해 임의 노드 고정 금지 |
| 메시 생성·형상 거부 | 겹침, 작은 간격·각도, 사라진 영역, 요소 방향 | 형상·메시 진단을 읽고 재현 모델 단순화 |
| 과도 초기조건 불일치 | 초기장과 첫 시각 경계값 | 물리적으로 일치시키기; 솔버가 초기값을 투영하지 않음 |
| Joule 반복 실패 | reason, 재료 범위, history, 비선형 defect | 되먹임과 타당한 초기·반복 설정 확인; 수용 기준 완화 금지 |
| 기존 경로 저장 거부 | 기존 파일과 출력 소유권 | 이전 결과를 보존하고 새 폴더 선택 |
| Export layout 거부 | 저장한 `field_layout`과 exporter 지원 | NPZ·summary를 보존하고 지원 reader 사용 또는 내보내기 미지원으로 별도 보고 |

[메시 안내](../packages/meshine/overview.md)는 모서리 처리를 설명하며
[Joule 튜토리얼](../packages/galerkin/temperature_joule_tutorial.md)은 범위·반복 실패를 보여줍니다.
수치 실패만으로 물리적 불안정, 유일성 상실, 특정 과도 거동을 증명하지는 않습니다.

## CLI와 Studio는 같은 경로가 아님

문서 문제는 해석 전 `python -m simcase validate <model.json>`을 실행하세요.
스키마 문제를 잡을 수 있지만 이후 메시 생성이나 수치 실행 단계에서 실패할 수도 있습니다.
Python API 지원이 JSON이나 Studio 지원을 뜻하지 않습니다.

Studio에서는 화면에 나온 작업·오류를 보존하고 연결·capability 실패, 잘못된 draft,
실행 거부, 사용 중·자원 한계, 결과 불가용을 구분합니다. 읽기 실패를 복구하려고 해석을
반복 제출하지 마세요. 입력을 바꾼 뒤 남아 있는 오래된 화면은 새 모델의 결과가 아닙니다.

[실험 workspace](../packages/simcase/workspace.md)는 자체 capability와 입력·session 형식을
사용합니다. 가열 도파관은 설정 미리보기이므로 연계 카드가 보인다고 연계 계산이 가능한
것은 아닙니다. 후보 index도 모드 추적을 뜻하지 않으며, 각자 정규화한 색상은 공통 전력
척도가 아닙니다. 기존 [정상](../packages/simcase/thermal_studio.md)·
[과도](../packages/simcase/thermal_transient_studio.md) Studio는 별도 복구·자원 정책을 따릅니다.

## 유용한 문제 보고

최소 입력, 정확한 명령 또는 UI 순서, 릴리스·커밋, Python·패키지 버전, 전체 오류와 실패
단계를 제공합니다. 예상한 물리 거동과 다른 해상도·인터페이스에서 같은 문제가 발생하는지도
적습니다. 수치 문제라면 단위·경계조건·세분화 설정·독립 기준해 또는 보존 검사를 포함하세요.
입력과 비교 방법 없는 그림을 검증이라고 부르지 않습니다. 공유 전 기밀 모델 데이터를
제거하세요. 보고 절차는 [기여 안내](../contributing.md)를 따르며, 완전히 확정된 결함이
아니어도 질문할 수 있습니다.
