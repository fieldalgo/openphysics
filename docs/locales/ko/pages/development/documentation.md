# 문서 배치와 번역

[English](../../../../development/documentation.md) | **한국어**

[문서 홈](../index.md)

문서 홈은 짧은 진입점으로 유지하고, 세부 목차는 독자의 목적에 따라 나눕니다.
각 문서는 한 원문을 유지하며 여러 목차에서 연결할 수 있습니다.

| 위치 | 담는 내용 |
|---|---|
| `getting-started/` | 설치와 첫 실행 순서 |
| `modeling/` | 형상·재료·메시와 패키지 연결 |
| `physics/` | 전자기·열·전기/Joule·역학별 인터페이스·계약·검증 경로 |
| `results/` | 저장·내보내기·물리 신뢰성 확인 |
| `guide/` | 작업별 사용 경로 |
| `reference/` | 패키지별 API·JSON 계약 목차 |
| `theory/` | 수식과 수치 방법 읽기 경로 |
| `validation/` | 독립 기준해, 수용 기록, 벤치마크와 과거 기록 |
| `development/` | 기여자 진입점과 문서 관리 |
| `packages/<package>/` | 기존 패키지 원문: 사용법, 구현 계약과 검증 기록 |

## 새 문서와 번역

1. 기존 원문에 속하는 내용이면 해당 문서를 갱신합니다. 새 패키지 문서는 `docs/packages/<package>/`에 둡니다.
2. 대응하는 한국어 문서는 `docs/locales/ko/pages/` 아래 같은 상대 경로에 둡니다. 영어 홈 `docs/README.md`의 한국어 대응은 `index.md`입니다.
3. 두 언어의 관련 목차에 링크하고 양방향 언어 링크를 넣습니다. 단위·수식·명령·허용치·출처·날짜·한계를 보존합니다.
4. 사용 안내, 규범적 계약, 측정 결과, 과거 기록을 구별합니다. 새로운 이론이나 검증 결과를 목차에서 만들어내지 않습니다.

기존 패키지 경로는 인용과 연결을 위해 유지합니다. 별도 원문 이동이 필요하면 모든 상대 링크,
이미지, manifest와 코드 참조를 함께 갱신하세요. 공개 문서는 저장소에 포함된 자료 또는
접근 가능한 공개 출처를 인용하고, 개인 경로나 세션 기록은 포함하지 않습니다.

## 링크 검사

저장소 루트에서 새 파일을 stage한 뒤 실행합니다. 검사기는 추적 중인 Markdown만 읽습니다.

```sh
python tools/check_markdown_links.py
python -m pytest -q tools/tests/test_markdown_links.py tools/tests/test_readme_links.py
```

이 검사는 외부 URL을 가져오거나 물리 정확도를 검증하지 않습니다. 전체 기여·CI 절차는
[기여 안내](../contributing.md)와 [개발·검증 안내](../development.md)를 따릅니다.


## OpenPhysics의 분류 기준

모델 구성→물리→실행→결과의 순서를 기본 경로로 유지합니다. 물리별 안내는 Python 엔진,
JSON/CLI, Studio를 구분하고 같은 메시·연계 방향·단위·경계조건의 제약을 드러냅니다.
패키지 목차는 import/API를 찾는 별도 축이며, 물리별 설명을 패키지 이름만으로 숨기지 않습니다.
검증 기록은 사용자 설명과 분리하되 각 물리 페이지에서 연결합니다. 새 기능은 해당 물리·
인터페이스 목차와 한·영 API/검증 링크를 함께 갱신합니다. 실제 교재나 설계 문서가 생기기
전에는 빈 학습·설계 분류를 만들지 않습니다.
