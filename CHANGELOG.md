# Changelog

All eight OpenPhysics distributions (`galerkin`, `galerkin-refsol`, `meshine`,
`gmshio`, `physmat`, `simcase`, `sipi` and the `openphysics` meta distribution) release
together under one version number. This file records what each release changes.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Stability in 0.x

0.x releases are alphas.

- The Python API of every package may change in any minor release (0.1 to 0.2).
  Patch releases (0.1.x) fix bugs and are not meant to change the API.
- What does not change in 0.x is how the Python API states units and names. The
  public functions, classes and results of physmat, galerkin and refsol take and
  return SI values under physmat registry names (`physmat.units`). A quantity
  is a keyword argument with no dimensional default, and text in place of a
  number raises `TypeError`. Their complex values follow exp(-i omega t): a passive loss has a
  non-negative imaginary part. `galerkin.kernels`, `physmat.kernels` and every
  module or name that starts with an underscore are internal: they keep units of
  their own, and simcase and sipi may call them, but they carry no promise and may
  change in any release. The names that the units and naming batch removed get
  no alias: no release carried them.
- The JSON model document format `"openphysics": "0.3"` is a contract: a document
  that is valid in this format keeps validating and keeps its meaning. A change
  that would break that gets a new format version. Format 0.2 documents are not
  read: every reader refuses one by name (`E-FORMAT` at `openphysics`, with what to
  write instead).
- Saved result format and field layout identifiers, such as
  `thermal.steady2d-result-v3` or `cavity3d-edge-v2`, are contracts: a file
  carrying an identifier keeps that layout. A changed layout gets a new identifier.
- Every identifier that results, Studio payloads and adapters carried before the
  units and naming batch is retired. A retired identifier is never given to
  another layout, and `simcase.export` refuses a file that carries a retired field
  layout by name (`simcase.export.RETIRED_LAYOUTS` names the layout that replaced
  each one):
  - result formats: `thermal.steady2d-result-v1`, `thermal.steady2d-result-v2`,
    `thermal.transient2d-result-v1`, `thermal.transient2d-result-v2`,
    `thermal.steady2d-regions-result-v1`, `thermal.transient2d-regions-result-v1`,
    `thermal.axisymmetric-regions-result-v1`,
    `thermal.axisymmetric-transient-regions-result-v1`, `electric.steady2d-result-v1`,
    `joule.steady2d-result-v1`, `joule.temperature2d-result-v1`,
    `electric.steady2d-regions-result-v1`, `joule.steady2d-regions-result-v1`,
    `mechanics.elasticity2d-result-v1`, `mechanics.thermoelastic2d-result-v1`,
    `mechanics.elasticity2d-regions-result-v1` and
    `mechanics.thermoelastic2d-regions-result-v1`;
  - field layouts: `thermal2d-p1-node-cell-v1`, `thermal2d-p1-node-cell-boundary-v2`,
    `thermal2d-transient-p1-node-cell-v1`, `thermal2d-transient-p1-node-cell-boundary-v1`,
    `thermal2d-p1-node-cell-regions-v1`, `thermal2d-transient-p1-node-cell-regions-v1`,
    `thermal-axisymmetric-p1-node-cell-regions-v1`,
    `thermal-axisymmetric-transient-p1-node-cell-regions-v1`, `electric-joule2d-p1-v1`,
    `electric2d-p1-node-cell-regions-v1`, `electric-joule2d-p1-node-cell-regions-v1`,
    `mechanics2d-p1-v1`, `thermoelastic2d-p1-v1`, `mechanics2d-p1-regions-v1`,
    `thermoelastic2d-p1-regions-v1`, `em-modes2d-p1-node-centroid-v1`,
    `em-modes2d-subspace-raw-v1`, `cavity3d-edge-v1` and `cavity3d-edge-complex-v1`;
  - result schemas and field representations: `openphysics.modes2d/2`,
    `openphysics.pml-candidates/1`, `vector-edge-nodal-v1`,
    `vector-subspace-edge-nodal-v1`, `pml-scalar-nodal-v1` and `pml-vector-edge-nodal-v1`;

- The physics provider protocol of `simcase.providers` (protocol version 1, entry-point
  group `openphysics.providers`) is unstable in 0.x: the provider attributes, the manifest
  layout and the provider listing may change in any minor release. A provider declares
  the protocol version it implements, and simcase lists a provider of another version as
  unavailable, by name.

The first release of the six implementation packages and the `openphysics` meta
distribution on PyPI, planned as 0.0.2 (0.0.1 is taken by the empty name
reservations, and PyPI does not reuse a version).

### Added

- Passive complex scalar/full-vector waveguide modes, complex resolved sweeps, dB/cm attenuation, and Studio/JSON/NPZ output; [signs and limits](docs/packages/simcase/lossy_modes.md).

- Add explicit same-mesh steady electric-to-heat coupling and mesh-bound
  element heat sources, with analytical and independent reference validation.

### Changed

- `openphysics` is a meta distribution: it has no code and requires the six
  implementation packages. Its extras `studio`, `export` and `rii` install
  `simcase[studio]`, `simcase[export]` and `physmat[rii]`. No extra installs Gmsh.
  The earlier `openphysics` 0.0.1 was an empty name reservation, like the 0.0.1
  of the other six names.
- Every package requires Python 3.12 or later. The minimum numpy, scipy, shapely
  and matplotlib are now 1.26, 1.11.2, 2.0.2 and 3.8, their first releases with
  Python 3.12 wheels.
- Requirements between the packages are limited to the 0.0 series
  (`>=0.0.2,<0.1`).
